# Frontend pipeline

## Stack and scope

- Используйте React 19, TypeScript, Vite, MUI и Emotion, уже установленные в
  `package.json`.
- Не добавляйте Tailwind, shadcn/ui, Better Auth или другую библиотеку
  компонентов/аутентификации без явной задачи. Аутентификация и авторизация
  задаются backend и `SPEC.md`.
- Перед изменением пользовательского поведения прочитайте затронутые разделы
  `SPEC.md`; frontend не дублирует серверные проверки прав и бизнес-правила.

## Обязательный выбор навыков

- Любой `.ts`/`.tsx` код: `typescript-clean-code` и
  `vercel-react-best-practices`.
- Новый или изменённый видимый интерфейс: `ui-ux-pro-max`; для токенов,
  темы или общих спецификаций компонентов — `design-system`.
- Переиспользуемый или составной React-компонент: `vercel-composition-patterns`.
- Перед завершением UI-изменения: `web-design-guidelines` для изменённых
  файлов.
- Сквозной пользовательский сценарий, воспроизводимый в локальном браузере:
  `agent-browser` для проверки реального поведения. Если браузерная среда
  недоступна, не заявляйте о такой проверке и зафиксируйте это как ограничение.
  В Windows используйте project config `agent-browser.json`: он запускает Chrome
  в headed-режиме, необходимом в текущем окружении. Используйте отдельную
  именованную сессию и закрывайте её после проверки.

## Реализация и тестирование

- Новое или изменённое пользовательское поведение требует теста на наблюдаемый
  результат: состояния loading/error/empty/success, валидация и доступность —
  когда они затронуты. Не пишите тесты, завязанные на внутреннюю реализацию.
- После каждого frontend-изменения запускайте из `frontend/`:

  ```powershell
  npm run check
  ```

- Исправляйте сбои проверки в пределах задачи. Не отключайте правила lint,
  typecheck и тесты без явной технической причины и согласования.
